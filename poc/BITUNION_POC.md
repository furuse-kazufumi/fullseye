# Precision-Union PoC — 発案の検証結果(honest)

**発案(ユーザー, 2026-09-02):** 「ユニオン型のようにビット深さを複数パターンに分割し、
量子化された要素をそれに乗せて一元的に処理できれば、省メモリ・高速化につながる。」

これを文字どおり実装した: 画像をタイル分割し、各タイルを**局所値域が要求する最小ビット幅**
{0,1,2,4,8,16} でアフィン量子化(= 精度のユニオン型)。真のビットパッキング(`np.packbits`)で
実メモリを計測。単一インターフェース(`scale_shift`/`threshold`/`sum`/`to_dense`)で
基盤ビット幅を問わず一元処理。実装 = `bitunion.py`、ベンチ = `bitunion_bench.py`、
正当性テスト = `../tests/test_bitunion_poc.py`(9件パス)。

これは既存の **exact geometric predicates と同じ形**: predicates は精度軸を
{float64, exact-rational} の2値ユニオンとし、入力ごとに測った誤差限界で選ぶ。本 PoC は
{0..16bit} のユニオンをタイルごとに測った値域で選ぶ。どちらも「証明可能に十分な最安の表現」を
選び、選択を1つの呼び出しに隠す。

## 測定結果(tile=16, 256×256)

### メモリ + 忠実度 — **本命の勝ち**
| 配列 | union/u8 | union/f32 | maxerr | ビット内訳 |
|---|---|---|---|---|
| binary mask | **0.17x** | 0.04x | 0 | 大半 0bit(定数タイル) |
| depth map(区分平坦) | **0.28x** | 0.07x | 0.002 | 128タイル 0bit + 128タイル 2bit |
| label map / 6クラス | 0.66x | 0.16x | 0 | 全 4bit |
| smooth gradient(f64) | 0.75x | 0.19x | 0.48 | 4bit×208 + 8bit×48 |
| HDR blob(f64) | 0.98x | **0.24x** | 0.99 | 1..8bit 混在 |
| photo+noise(u8) | 1.16x | 0.29x | 0 | 全 8bit — **u8 に負ける** |
| uniform noise(u8) | 1.16x | 0.29x | 0 | 全 8bit — **u8 に負ける** |

- **勝つ:** mask/depth/label/smooth と、**f64/f32 の実数データ**(vs f32 で常に 0.2x 前後)。
- **負ける:** 高エントロピー u8(写真ノイズ・一様乱数)。タイルヘッダが純オーバーヘッドで
  dense uint8 より **大きくなる**。コンテナはこれを隠さず正直に報告する(テストで固定)。

### 速度
- **アフィン連鎖(20 op → 1回 materialize): 2.34x 高速。** 遅延部分(materialize しない
  O(タイル数)のヘッダ代数)だけなら **143x**。`v = a·(off+scale·code)+b` から
  `off' = a·off+b, scale' = a·scale` でコードを一切触らない — トリックでなく代数。
  op を積むほど差が開き、decode は最後の1回だけ。
- **threshold: union が 43x 負ける(honest finding)。** dense の `arr > t` は完全ベクトル化の
  単一パス(≒メモリ帯域律速)で 0.004ms。「片側タイルを O(1) で飛ばす」コード空間近道は
  **Python タイルループからは勝てない**。ベクトル化/コンパイル済みカーネルか、そもそも
  dense に materialize しない運用でのみ意味を持つ。

## 結論(正直な内訳)
1. **省メモリは本物で広い** — 実数(f32/f64)データと低エントロピー(mask/label/depth)で
   確実に勝つ。オーバーヘッドを正直に報告するので「常に得」の嘘をつかない。
2. **遅延アフィンの高速化は本物かつ数学的に説明可能** — O(タイル数)、連鎖で伸びる。
   fullseye の点演算パイプライン(明るさ/コントラスト/正規化の連鎖)に直結しうる。
3. **コード空間 threshold の高速化は Python では実現しない** — dense numpy が既に最適。
   ここは「発案どおりに速くなるとは限らない」実測反例。

## 昇格するなら(次段階、未着手)
- 遅延アフィン層を fullseye の点演算 op に被せる(`scale_shift` を Op として登録し、
  materialize を遅延)。**近傍 op(畳み込み/モルフォロジ)はタイル境界を跨ぐので decode 必須** —
  ここは省メモリ(入力側)だけで計算の近道は無い、という境界を明記した上で。
- f32/f64 データセット(depth/HDR/測定量)を主対象にすれば vs f32 で常時 4x 前後の省メモリ。
- threshold/reduction をベクトル化(タイルを bit 幅でグルーピングして numpy 一括)すれば
  Python ループ税を外せる可能性。ただし dense の自明さを上回れるかは要再実測(零点を疑う)。
