# GPU 第 4 便: 光路・波長・偏光の一括計算(2026-11-02)

`lens_gpu.py`(近軸・実光線・分光・公差 MC)と `polar_gpu.py`(偏光光線追跡・Jones / Mueller・偏光画像)の測定記録。
すべて `tools/bench_gpu_optics.py` の出力で、数字は `docs/perf/gpu_optics_2026-11-02.json` にある。
時間は転送(CPU → GPU → CPU)込み。`best` は 2 回目以降の最良、`first` は最初の 1 回(起動込み)。
float64 が既定。外挿した数字はこの文書に無い。打ち切ったものは打ち切ったと書いた。

測定中は別のエージェントが同じ機械で CPU と GPU を使っていた。CPU の時間には数十 % の揺れがある(同じ triplet の MC 1 万案が、自分の別の処理と重ねなかった回で 42.6 s、重なった回で 73.6 s)。
★最初の CPU 一括の測定では triplet の 2501 波長が 16〜19 s と出たが、`regen_all` と重なっていた。分解して測ると 0.8 s で、表は自分の重い処理を止めて測り直した値にした。倍率の桁は読めるが、有効数字 2 桁目は信用しないこと。

GPU: NVIDIA GeForce RTX 5090(float64)。実行中の最大メモリ 20.2 GB。

### 門の目安 1e-9 mm を超えた処方: `two_mirror`(1.7e-08 mm)、`paraboloid` は超えないが他より 4 桁大きい(1.2e-10 mm)

原因は `raytrace._intersect_conic` の丸めで、`lens_gpu` の誤差ではない。放物面(k = -1)の軸の近くで 2 次方程式の A が 7.6e-9 まで小さくなり、`(-B ∓ √D)/(2A)` の小さい方の根が桁落ちする。60 桁の計算と比べると、CPU の交点は 7.2e-9 mm ずれていた。`lens_gpu` は安定な形 `C/q` で解くので 1e-11 mm 以内に入る(`test_conic_root_beats_cpu_on_a_paraboloid`)。CPU 側は値が変わるので今回は直していない。

閉形式の検算: 単一屈折面、厚肉レンズ(`thick_lens` の 5 量)、鏡 f = -R/2、放物面鏡と Descartes 非球面の軸上無収差(1e-9 mm 以内)、平面の Snell、平行平板の分光透過 (1 - R)² と内部透過 `exp(-αt)`、単一面の Fresnel の s / p、ブルースター角で T_p = 1、Malus、光線ごとの Mueller 行列の `mueller_checks`(physical / pure / passive)。

`lensimage.through_focus_mtf`(焦点 1 位置)とは絶対差 1e-8 以内で一致。`optics` の素子、`stokes_analyze`、`polarization_demosaic`、`photoelastic_polarization_images`、`sfp_render`、`dolp_to_zenith` も同じ入力で 1e-10 以内(テストの門)。

### 1 回だけ小さく呼ぶ場合は負ける

近軸 1 回・光線 127 本 1 回は、torch の方が既存 numpy より遅く、GPU はさらに遅い。テンソルの組み立てと演算ごとの間接費が仕事より大きい。`device="auto"` は仕事量 1,000,000(設計案 × 波長 × 面 × 127 本)未満なら CPU を選ぶ。小さい呼び出しは今までどおり `raytrace` を使うのが正しい。閾値の根拠: 301 波長 × 127 本 × 6 面(約 23 万)は torch CPU が勝ち、1 万案 × 127 本 × 6 面(約 760 万)は GPU が 12 倍勝つ。

### 異常に速い値の内訳

公差 MC 1 万案の GPU / 既存が 603 倍と大きい。単純な GPU の演算速度の差ではなく、内訳は 2 段ある。

- 既存は 1 案ごとに `lens_system` の検証、辞書の組み立て、`paraxial_trace` を Python で回す(1 案 1.69 ms)。この間接費が大半で、同じ torch を CPU で動かすだけで 29 倍縮む。
- 残りの 21 倍が torch CPU → GPU の差で、これが演算の実力に近い。

値の側の確認: 実演 1 の `rms_spot` の平均は GPU 0.03860514369689、torch CPU 0.03860514369689 で 13 桁一致した。計算を省いた結果ではない。時間は `.cpu()` で結果を手元に戻すまでで、`synchronize` も入っている。

GPU の実行中メモリの最大は 20.2 GB(float64)。CARLA と同時に動かすなら `tolerance_monte_carlo(chunk=...)` で小さくする。既定の分割は空きメモリの 1/2 まで。

| catalog_doublet | 7.46e-06 | 2.46e-07 | 0 | 1.53e-04 |

MC の RMS はスポット半径の小さい案で丸めに負ける。公差の分布を読むなら float64 を使う。demosaic の float32 の差は最大 9.1e-08(値域 1)。

## 5. 扱わないもの

- `lens_gpu` は理想レンズ面 `f`、`zernike_sag`、`afocal`、ケラレ係数、`aim="stop"` を `ValueError` で断る。物体側テレセンは `failed` の印で返す。
- 分光透過の吸収は `materials` に k がある媒質だけ効く。同梱の Sellmeier 20 種と `(nd, vd)` は吸収 0 になる。コートと多重反射は入っていない。
- 偏光光線追跡は実数の Fresnel 係数なので、コートなしの界面の二色性と基底の回転だけを表す。リターダンスは生じない。
- `lensopt` / `chromconf` / `lensglobal` の呼び出し元はまだ `raytrace` のままで、この一括経路へ繋いでいない。
- 公開 op は足していない(下回りの部品)。`tests/test_public_reachability.py` の不可視関数の総数を 948 → 977 に上げた。
