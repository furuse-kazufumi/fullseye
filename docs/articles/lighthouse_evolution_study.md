# Lighthouse 仮想工場: Fullseye 自律探索（C4）

## 探索経路と評価規律

Fullseye の本線は `evolve.run` の「型付き genome → op 列 → train 選抜 → locked
holdout 1 回」である。`pipeline_evolve.py` は旧3D PoC、`evolve_params.py` はその
パラメータ共進化版、`opsearch.py` / `imgevolve.py` は索引と実行UIであり、今回の
選抜器ではない。Lighthouse adapter は同じ規律で `varmodel_score`、`gopen` / `gclose`、
特徴集約、判定を型付きに合成する。新しい op は追加していない。

学習240 seedの先頭2/3を fit、末尾1/3を search-validation とした。最終評価800 seed
は探索関数が受け取ると例外にし、確定後にだけ採点した。目的関数は
`見逃し% + 過検出% + 2 max(過検出%-5, 0)`。良品validationの95%裾でも閾値を
較正した。基準と手組みも同じ学習データ、最大48評価で調整した。

WEF値は各実工場の導入前との比較であり、この仮想工場との勝敗を表さない。目安の
「2用途で両指標とも基準・手組みに有意に勝つ」には届かなかった。両指標が数値上
ともに勝ったのはSMTだけである。タイヤは過検出、ホイールと開先は見逃しを改善したが、
もう一方が悪化した。したがって研究目標を達成したとは扱わない。

## FAR 較正と律速

宣言 pixel FAR 0.001 に対する実測は、タイヤ0.00511、ホイール0.00198、SMT
0.00245で、従来どおり宣言を2〜5倍超えた。validation裾較正後の部品単位宣言FAR
0.05に対する最終実測はタイヤ0.0633、ホイール0.3459、開先0.1643、SMT0.0269。
SMTだけが守り、裾較正だけでは分布シフトを吸収できない用途が残った。

律速は、タイヤではコード周期と低コントラスト欠陥の分離、ホイールでは回転・肉厚
変動と局所欠陥の混同、開先では点欠測がRANSAC角度の裾を太くすること、SMTでは
微小open/voidが正常はんだ量変動に埋もれることである。次便で必要な op は、
周期推定付きノッチ、回転・スケール対応のCAD位置合わせ、位置依存/局所共分散の
variation model、連結部の幅・neckを測るトポロジー特徴、開先の角度とルート面を
同時に拘束する頑健fit、分布シフトに対するconformal tail calibrationである。
