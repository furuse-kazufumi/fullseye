## この記事で扱うこと

シミュレーションの絵と実物の写真が合わないとき、模型の係数(焦点距離、屈折率、膜厚、カメラの利得など)を写真に合わせて直したくなります。このシリーズの出発点は、著者が書いた次の 2 行です。

> 実物の画像を与えられたら、誤差をフィードバックして計算に使う係数を自動的調整するようなことができるといいな
>
> 多変量解析みたいなことから入るんじゃなかろうか?

前半はよくある「最小二乗で合わせる」です。後半が要点で、合わせる前に「どの係数が写真から決まるのか」を調べておかないと、合わせた結果を信用できません。この記事では、その理由を 3 つの具体例で示します。

先に結論を書きます。

- 当てはまりの誤差が小さいことは、係数が正しいことを意味しません。写真からは決まらない係数の組(交絡)があり、模型が足りないと係数がゆがんだまま合ってしまいます。
- 合わせる前にそれを見つけるのが多変量解析です。どの条件で撮るか(実験計画)、どの係数が絵を動かすか(感度)、どの係数が同じ動きをするか(交絡)を調べます。
- 合わせた後にそれを見つけるのが、同定性(どこまで決まるか)、取り置いた写真での検証、残差の主成分分析、雑音の大きさを基準にした絶対の χ² 検定です。

例はすべてオープンソースの画像計測ライブラリ Fullseye(<https://github.com/furuse-kazufumi/fullseye>)にあるツアーで再現可能です。記事の数字は、次の 2 本を実行した印字と照合してあります。

```bash
py -3.11 examples/simcal_tour.py
py -3.11 examples/simcal_checks_tour.py
```

## 用語

| 用語 | かみくだくと | この記事での使い方 |
|---|---|---|
| つまみ(knob) | 模型の中で、写真に合わせて動かす係数 | 照明の強さ、利得、屈折率 n、膜厚 d、焦点距離 f |
| χ²/自由度 | 残差を雑音の大きさで割って二乗し、平均したもの | 1 なら「残差は雑音そのもの」。60 なら雑音の 60 倍ずれている |
| 交絡 | 2 つのつまみが写真を同じように動かすこと | 決まるのは片方ずつではなく組み合わせ(積など)だけ |
| 同定性 | 写真からつまみが 1 つの値に決まるかどうか | 決まらないなら、値を返さずに拒否する |
| 保留画像(holdout) | 当てはめに使わず、取り置いた写真 | 当てはめた模型が「初めて見る写真」でも合うかを見る |
| 残差 PCA | 残差の写真を主成分に分けること | 雑音より大きな「形」が残っていれば、模型に足りないものがある |

## 例 1: 利得 x 照明は、積しか決まらない

### かみくだき

写真を明るくするつまみが 2 つあるとします。照明の強さと、カメラの利得です。照明を 2 倍にして利得を半分にすると、写真はまったく同じになります。写真から決まるのは「照明 x 利得」の積だけで、照明と利得を別々には決められません。

当たり前に聞こえますが、最小二乗のソフトに 2 つとも渡すと、たいていは何かしらの値が返ってきます。その値は出発点しだいで変わる 1 点で、真値とは関係がありません。

### 図と数字

冒頭の図は、照明を 0.4〜4 の 13 点に決め打ちにし、そのたびに利得を合わせ直した結果です。真値は照明 1.5、利得 600(積 900)です。合わせ直した利得はどれも「利得 = 900 / 照明」の線に乗ります。

次の図は、そのときの当てはまりの良さ(χ²/自由度)です。どの点も 0.94 前後で、雑音どおりの 1 を少し下回ります。照明を 0.4 にしても 4 にしても、写真の説明力は同じです。

![線の上ならどこでも同じだけ合う](https://raw.githubusercontent.com/furuse-kazufumi/fullseye/master/docs/articles/assets/qiita_simcal_series/valley_chi2_ja.png?v=1)

Fullseye の当てはめ(`simcal_fit`)は、この場合に値を返さずに拒否し、決まる組み合わせだけを報告します。

- 決まる組: `illum^1 * gain^1 = 899.4`(真値 900、ずれ 0.06 %)
- 照明と利得を 1 つずつ: 値を出さない(空の辞書)
- 照明を 1.5 に固定すると: 利得 = 599.6(真値 600)

決まらないつまみがあるときは、どれかを別の手段(照度計、カタログ値など)で固定するか、そのつまみを動かす撮り方に変えます。単波長で撮った膜も同じ形で、屈折率 n と膜厚 d は別々に決まらず、決まるのはほぼ n·d(光路長)だけです。

## 例 2: 干渉次数を取り違えた当てはめは、相対の門を全部通る

### かみくだき

シリコンの上に透明な膜(n = 1.46、d = 520 nm)があり、400〜700 nm の 31 波長で反射を撮ります。反射率は波長に対して波打ち、山と谷の数は膜厚で決まります。χ² の地形には干渉の次数ごとに谷が並ぶので、出発点が悪ければ、行き先は隣の次数の谷です。

落ちた先でも、当てはめは「それなりに」合って見えます。問題は、よく使われる検証がどれも相対的な比較だということです。

### 図と数字

![隣の干渉次数に落ちた当てはめ](https://raw.githubusercontent.com/furuse-kazufumi/fullseye/master/docs/articles/assets/qiita_simcal_series/film_orders_ja.png?v=1)

小さな計画(出発点 2 つ)から始めた Levenberg-Marquardt は、n = 1.329、d = 356.5 nm に落ちました(破線)。χ²/自由度は 60.4 です。出発点を 16 個にした multistart は、n = 1.4591、d = 520.7 nm(χ²/自由度 0.93)に着きました(実線)。

この 2 つの結果を、取り置いた写真(保留画像)を使って `simcal_validate` の 6 つの門にかけたのが次の表です。

| 門 | 比べるもの | 隣の次数 | 正しい次数 |
|---|---|---|---|
| 1. 初期値より良いか | 当てはめ前の χ² | 通る | 通る |
| 2. 保留 / 学習 ≤ 1 + τ | 学習の写真と保留の写真の誤差の比 | 通る | 通る |
| 3. 利得と黒だけの模型より良いか | いちばん単純な模型 | 通る | 通る |
| 4. 範囲・事前・端 | 値が範囲の端に張りついていないか | 通る | 通る |
| 5. つまみ ≤ 画像の方向の数 | 過適合 | 通る | 通る |
| 6. 絶対: χ² の上側確率 p ≥ 0.001 | 雑音の模型 | **落ちる** | 通る |

隣の次数の当てはめは、初期値より良く、保留画像でも学習と同じ程度に合い(保留の χ²/自由度は 53.1 で、学習の 60.4 より小さい)、単純な模型にも勝ちます。1〜5 番の門はどれも「何かと比べて良いか」を見ているので、全部通ります。

「雑音の何倍ずれているか」を見るのは 6 番目の門だけです。学習で χ²/自由度 60.4、保留で 53.1 は、雑音どおりなら起きる確率がほぼ 0(p < 0.001)なので、ここで初めて拒否されます。

この門には弱点もあります。雑音を大きく見積もりすぎると(分散を 4 倍にすると)p は 1 に張りつき、門は通ってしまいます。雑音の過大評価は χ²/自由度が 1 よりずっと小さいことでしか見えません。雑音の模型はカメラの測定(EMVA 1288 のような線形カメラの模型)で決めておく必要があります。

## 例 3: 族の外のデータは、残差 PCA が形で知らせる

### かみくだき

模型の「族」とは、つまみをどう動かしても作れる絵の集まりです。光軸が中心からずれたレンズの周辺減光は、中心対称の cos⁴ の模型ではつまみをどう動かしても作れません。族の外のデータです。

それでも当てはめは数を返します。足りない分をどれかのつまみが吸い込んで、ゆがんだ値で合わせるからです。

### 図と数字

光軸を (5, −4) px ずらしたレンズで平らな板を 4 段の露光で撮り、中心の cos⁴ 模型(つまみ: 焦点距離 f、利得、黒レベル)で合わせました。

- f = 41.75 px(真値 40)。値は返りますが、4 % ずれています
- χ²/自由度 = 31.6

![族の外: 光軸のずれたレンズ](https://raw.githubusercontent.com/furuse-kazufumi/fullseye/master/docs/articles/assets/qiita_simcal_series/out_of_family_maps_ja.png?v=1)

左から、撮った平板、残差(雑音で割ったもの)、4 枚の残差の主成分分析の第 1 成分、真のずれ(ずれたレンズの絵 − 中心の模型の絵)です。第 1 成分の形は真のずれと相関 0.99 で一致します。

![残差 PCA の特異値](https://raw.githubusercontent.com/furuse-kazufumi/fullseye/master/docs/articles/assets/qiita_simcal_series/pca_singular_values_ja.png?v=1)

雑音だけなら、特異値はランダム行列の理論で決まる端(Tracy-Widom 分布の 99 % 点、ここでは 42.6)の下に収まります。光軸がずれたレンズでは第 1 特異値が 444 で、端の 10 倍を超えています。光軸がずれていない写真(族の中)では、4 つとも端の下です。`simcal_discrepancy` はこの場合「雑音を越える構造が 1 成分ある。不確かさは楽観側」と注記します。

残差 PCA は「何が足りないか」の形を示します。この例なら、第 1 成分から「減光の中心がずれている」と読み取れるはずです。そこから模型に光軸の位置のつまみを足すかどうかを決めます。

## どう使うか

1. 合わせる前に、つまみごとの感度を測り(`simcal_screen`、Morris のふるい)、効かないつまみと交絡している組を見つける。
2. 決まらない組があれば、撮り方を変える(波長を増やす、チャートを撮る)か、どれかを外部の値で固定する。
3. 当てはめる(`simcal_fit`)。谷がいくつもある問題では multistart を使う。
4. 取り置いた写真で 6 つの門にかける(`simcal_validate`)。絶対の χ² の門を外さない。
5. 残差 PCA(`simcal_discrepancy`)で、模型に足りないものの形を見る。

```python
import fullseye as fs
L = fs.ledger

obs = L.simcal_observe(model, images)          # 模型と写真を組む
screen = L.simcal_screen(obs)                  # 効く / 効かない / 組でしか効かない
fit = L.simcal_fit(obs)                        # 決まらないつまみがあれば拒否
checked = L.simcal_validate(fit, holdout)      # 6 つの門
report = L.simcal_discrepancy(checked)         # 残差 PCA
print(L.simcal_report(report)["text"])
```

`model` の組み立て方は examples/simcal_tour.py の先頭にあります。

## 向かないこと

- 位置合わせは整数画素だけです。サブ画素のずれは残差に残ります。
- 推定の物差しはカメラの雑音模型です。雑音を見誤ると、下界も区間も見誤ります。
- 谷がいくつもある問題で、出発点が少ないと隣の谷に落ちます。値は返し、警告と 6 番目の門で知らせます。
