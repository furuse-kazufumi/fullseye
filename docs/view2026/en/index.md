## Try it yourself

Run the paper's figures yourself, on a phone too. Switch methods with the tabs and drag the 3-D views to rotate them.

- **[CAD versus a scanned point cloud](../viewers/poc_cad_scan_deviation.html?lang=en)**: Alignment absorbs defects: a part whose true value is 1.2 µm shows a 121 µm dent that does not exist.
- **[LiDAR terrain change](../viewers/poc_lidar_terrain_change.html?lang=en)**: Plain differencing makes the whole unchanged block look 0.183 m lower. Correct it and only the real change is left.
- **[Template tracking](../viewers/poc_template_tracking.html?lang=en)**: Even after it switches to a look-alike object, the tracker keeps reporting 'found'.
- **[Pulse thermography depth](../viewers/poc_thermography_ndt.html?lang=en)**: Cutting the fit window from 25 s to 4 s shrinks the worst depth error of small flaws from +627% to ±14%. The cause was the choice of window, not the physics.
- **[Talbot carpet and grating X-ray images](../viewers/poc_grating_interferometry.html?lang=en)**: In absorption the crack's contrast-to-noise ratio is only 1.34; in dark field it rises to 13.5, and turning the grating even reveals the fibre direction.
- **[Micron dents in a mirror image of stripes](../viewers/poc_phase_measuring_deflectometry.html?lang=en)**: In a photograph the signal is 0.17 times the noise and nothing shows; in the curvature map built from the mirror image of stripes, a dent 1 µm deep stands 57 times above the noise.
- **[How sharply an asteroid's surface bends](../viewers/poc_asteroid_curvature.html?lang=en)**: Curvature computed from the points of a real asteroid, with ridges and boulder edges shown in colour. The ruler is checked first on a sphere whose answer is known.
- **[Focus stacking](../viewers/poc_focus_stacking.html?lang=en)**: Re-runs the PoC function while sweeping f-number over 2.0–16.0.
- **[White-light steps](../viewers/poc_interferometry_step.html?lang=en)**: Re-runs the PoC function while sweeping noise σ over 0.000–0.120.
- **[Polarization](../viewers/poc_polarization_specular.html?lang=en)**: Re-runs the PoC function while sweeping incidence angle over 0–80°.
- **[Photoelasticity](../viewers/poc_photoelasticity.html?lang=en)**: Re-runs the PoC function while sweeping analyser angle over 0–135°.
- **[Fly compound eye](../viewers/poc_compound_eye.html?lang=en)**: Re-runs the PoC function while sweeping per-view SNR over 0.5–16.0.
- **[Joint voids (CT)](../viewers/poc_ct_void_morphology.html?lang=en)**: Re-runs the PoC function while sweeping threshold over 0.2–0.8.
- **[Active contours](../viewers/poc_active_contours.html?lang=en)**: Re-runs the PoC function while sweeping iterations over 0–1000.

## What you see, and the measured number

Every number is measured against ground truth the PoC planted itself (closed form, analytic solution or published value); running the PoC prints the same value.

<div class="vl" markdown="1">

**Inspection and appearance**

- [Faint-defect limit](../../articles/assets/poc/poc_real_defect_floor/02_defect_floor_sweep.gif) (GIF): The same planted defect grows on a real brick texture and on a synthetic background with matched noise. **Even with matched noise, the detection limit on real textures is 2.03-3.47x the synthetic one (defects of known position and amplitude).** [source](https://github.com/furuse-kazufumi/fullseye/blob/master/examples/poc_real_defect_floor.py)
- [Active contours](../../articles/assets/poc/poc_active_contours/06_u_shape_snakes.mp4) (video): Classic snake (red) bridges the U-shaped notch; GVF (blue) reaches the bottom. Green is the true edge. **Swapping only the external force to GVF gives Dice 0.993 against the true edge.** [source](https://github.com/furuse-kazufumi/fullseye/blob/master/examples/poc_active_contours.py)
- [DIC strain](../../articles/assets/poc/poc_dic_strain/05_tensile_ramp.mp4) (video): Strain maps read from speckle images as the tensile load ramps up (the machine also rotates by 2 degrees). **True strain 3000 µε. Small-strain reads 2341 µε (rotation hides it); Green-Lagrange reads 2961 µε (theory 3005 µε).** [source](https://github.com/furuse-kazufumi/fullseye/blob/master/examples/poc_dic_strain.py)
- [1-D barcode](../../articles/assets/poc/poc_barcode_1d/03_collapse.png) (figure): A home-made simple code (not a real standard) damaged four ways, with success, misread and unreadable counted as three separate outcomes. Over the 384 images past the onset of damage, the strict decoder that checks run structure misreads 7.3 %, while the lenient decoder that always returns nine digits misreads 46.1 % — and has the higher success rate (47.7 % versus 40.1 %). The tilt cliff is pure geometry (predicted 15.95 degrees) and lands between 15 and 16 degrees. [source](https://github.com/furuse-kazufumi/fullseye/blob/master/examples/poc_barcode_1d.py)
- [Bearing diagnosis](../../articles/assets/poc/poc_bearing_diagnosis/03_sk_bands.png) (figure): An impulse train synthesised at the closed-form defect frequency (BPFO 104.556 Hz), sunk into noise, with detection rates of the raw spectrum and the envelope spectrum side by side. The worst SNR at which 10 of 10 seeds still detect is -0.9 dB for the raw spectrum and -18.4 dB for the envelope, a 17.5 dB gap. But a record with no defect at all still produces a global prominence of 43; had the threshold not been set from the null recording, this PoC would have been its own false positive. ## What Fullseye is

A foundation that hands physics simulation (including sensing such as optical design and 3-D measurement) and classic image processing to an AI through MCP and RAG, lets it work out a combination for each task, and solves the task interactively while checking type consistency and evaluating against ground truth. Open source (Apache-2.0).

<details markdown="1">
<summary><b>Try it</b> (Python 3.11)</summary>

```
pip install fullseye
git clone https://github.com/furuse-kazufumi/fullseye
cd fullseye
python examples/poc_focus_stacking.py
```

The focus-stacking PoC runs in about 20 seconds and prints its numbers against ground truth and `PASS`. Figures go to `out/figures/poc_focus_stacking/`.

- **Title**: Fullseye：型付き演算子と物理シミュレーションに基づく画像検査・三次元計測基盤 _(ja)_ (an image-inspection and 3-D measurement foundation built on typed operators and physics simulation)

- **Venue**: ViEW2026, Workshop on Practical Use of Vision Technology
- **Paper PDF**: [English](../paper/101_en.pdf) · [简体中文](../paper/101_zh.pdf)(日本語: available from 2026-11-26)

**Abstract (translated from Japanese)**: We propose Fullseye, an open-source foundation that builds image-inspection and 3-D measurement processing as chains of operators with declared input and output data types, evaluates it quantitatively against ground truth produced by physics and imaging simulation, and records the procedure, the evaluation and the failure conditions so they can be reused. It consists of about 3,000 typed operators, a check that rejects type mismatches before execution, multilingual operator search (RAG), and more than 200 proof-of-concept programs with ground truth. We report quantitative evaluation of representative examples and the distinction between synthetic, measured and real-hardware validation stages.
