# パラメータの窓(束を並べて見る・直す)

Fullseye Studio の「パラメータ」の窓の説明です。パラメータの束(`fullseye.load_params` が読むファイル)を、**行 = キー、列 = ファイル**の表に並べて見比べ、その場で直し、元の形式のまま書き戻します。束そのものの決まり(単位、参照、include、op への渡し方)は [PARAM_BUNDLE.md](PARAM_BUNDLE.md) にあります。

実装は 2 つのモジュールです。

| モジュール | 中身 |
|---|---|
| `studio_params_model.py` | 表のモデル(Qt なし)。読む・比べる・絞る・写す・直す・Undo / Redo・書く・外での変更の検出 |
| `studio_params_qt.py` | 窓(PySide6)。道具の帯・木つきの表・状態の 1 行 |

## 開き方

単独で開けます(Studio 本体が無くても動きます)。

```
python -m studio_params_qt rig_day.json rig_night.yaml rig_lab.xml
python -m studio_params_qt --lang ja rig_day.json
python -m studio_params_qt            # 前に開いていたファイルを戻す
```

Studio の中からは `studio_params_qt.show_params_window(parent, paths, tr, lang=言語コード, confirm=confirm_action, strip=列の部品を作る関数, strip_rule=向きの規則, overflow="scroll" | "wrap")` が入口です。同じ親の窓が既にあれば 2 枚目は作らず、渡したファイルを列に足して前に出します。窓はモードレスで、本体の操作を止めません。`confirm` に Studio の `confirm_action` を渡すと、確認の窓が Studio と同じ形になります(下の「確認の窓」)。`strip` / `strip_rule` / `overflow` は道具の列を Studio の全部のパネルと同じ動きにする 3 つです(下の「道具の列」)。渡さないと既定の部品のままで、規則が無いので横長の窓でも道具の列は上の 1 行です。

**Studio からは言語を `lang=` で渡します。** Studio の `tr` は Studio の表(`studio_assets/i18n.json`)だけを引き、この窓の文をほとんど知りません(同じ英語の文があるのは 9 行)。`tr` だけを渡すと窓がほぼ英語になります。`lang` を渡すと、この窓の対訳の表をその言語で引き、表に無い文だけを `tr` に任せます。Studio の言語を切り替えた時は `ParamsWindow.set_lang(言語コード)` を呼びます(下の「言語」。差し込んだ `FlowStrip` の送りのボタンの文も一緒に作り直します)。theme を切り替えた時は何も呼ばなくて構いません(パネルが自分で色と密度を読み直し、列の部品の色も描き直させます)。「収まらない時: 送る / 折り返す」を切り替えた時は `ParamsPanel.set_overflow(形)` を呼びます。

開いた時のフォーカスは、束があれば表、無ければパネルそのものに置きます(ボタンには置きません)。窓の中の文字のボタンは、Enter で押される既定のボタンになりません。

## 画面

上から、道具の帯・表・状態の 1 行です。

- **道具の帯**(アイコンだけのボタン。載せるとツールヒントに名前・何が起きるか・キーが出ます): 開く(Ctrl+O)/ 列を足す(Ctrl+Shift+O)/ 列を外す / 保存(Ctrl+S)/ 名前を付けて保存(Ctrl+Shift+S)/ 読み直す / 元に戻す(Ctrl+Z)/ やり直し(Ctrl+Y。Ctrl+Shift+Z も)/ 列へ写す / 違う行だけ(キーなし。帯のトグルだけ。Ctrl+D は Studio で「複製」なので付けません)/ キーを検索(Ctrl+F)。群の間には細い線が入ります。押せない道具は、ツールヒントに押せない理由を言います(「保存 — … · 今は押せません: 変更がありません (Ctrl+S)」)。検索の欄の中の虫眼鏡は Ctrl+F と同じ(欄へ行く)、× は検索を消します。
- **表**: 1 列目はキー(`camera.fx` の `camera` が節、`fx` が葉。節は折りたためます)、2 列目は行の印、3 列目から束が 1 つずつ。見出しは束の名前で、未保存なら `*`、読むだけの束なら「読み取り専用」と付きます。見出しのツールヒントに、ファイルの場所と、保存すると失われる物が出ます。
- **状態の 1 行**: 束の数・行の数・違う行の数・一部の束に無い行の数・未保存の束の数。右側に、直前の操作の結果や断った理由が出ます(断った時は ✕、注意は ▲)。窓が狭い時は、数え方が印と数だけの短い形になります(全文はツールヒント)。✕ と ▲ の知らせは読める事を先にします: 数え方を短い形にしても 1 行に入らなければ、数え方の行の上に折り返して全文を出します(4 行まで。知らせが消えれば 1 行に戻ります)。印の無い知らせ(済んだ事)は 1 行のままで、収まらなければ末尾が … になります(全文はツールヒント)。

### 道具の列(向きと、収まらない時)

道具の帯のボタンは、1 つの部品にまとまっています。道具は 1 機能 1 つの `QAction`(`ParamsPanel.tool_actions`)で、ボタン・キー・パネルの一覧はどれも同じ `QAction` を押します。

- **向き**: `ParamsPanel.set_strip_side("top" | "left")`(`left` = 表の左に縦の 1 列、検索の欄は表の上)。自動で選ばせる時は `set_strip_rule(fn)` に規則を渡します。`fn(幅, 高さ, 今の向き)` が `"top"` / `"left"` を返し、パネルの大きさが変わるたびに聞きます。Studio の全部のパネルで 1 つの規則(`studio_panels.strip_side`: 幅 / 高さが 2.2 以上で左、1.6 以下で上、間は今のまま)を渡す形です。

  ```python
  panel.set_strip_rule(lambda w, h, now: studio_panels.strip_side(w, h, now, mode))
  ```

- **既定の部品**(objectName `panelStrip`)は「送る」「折り返す」を持ちません。左に縦に置くには全部のボタンの長さが要るので、高さが足りない窓では上の横 1 行へ戻します(ボタンを詰めたり重ねたり切ったりしません)。`strip_side()` は頼まれた向き、`strip_side_shown()` は今置いている側です。高さが戻れば左へ戻ります。折り返した知らせ 4 行分の高さも先に取ってあるので、知らせが出るたびに向きが変わる事はありません(窓の高さ 378 px が境)。
- **差し替え**: `set_strip_widget(w)`。受ける形は 2 つです。
  - `set_actions(items)`(`QAction` と、群の区切りの `None` の並び)と `set_orientation(Qt.Orientation)` を持つ `QWidget`。objectName は `panelStrip` になります。
  - Studio の見た目の部品 `studio_panels` の `FlowStrip`(`set_groups(ボタンの群)` と `set_orientation("h" | "v")`)。そのまま差し込めます。パネルが `QAction` からボタンを作って群で渡し、名前(`flow_strip`)は付け替えません。本体の高さ(幅)を全部渡すので、収まらない分は `FlowStrip` が送る(両端の送りのボタン)か折り返します(`set_mode("scroll" | "wrap")`)。

    ```python
    strip = studio_panels.flow_classes()["FlowStrip"]("tools", "params")
    panel.set_strip_widget(strip)
    ```

  どちらの形も、`restyle(tr)`(言語と theme で描き直す)と `set_mode("scroll" | "wrap")`(収まらない時の形)を持っていれば、パネルが呼びます。差し込んだ時に今の言語と形を当て、以後は言語の切り替え(`set_tr` / `set_lang`)・theme の読み直し・`set_overflow` のたびに当てます。
- **収まらない時の形**: `ParamsPanel.set_overflow("scroll" | "wrap")`(`overflow()` が今の形。知らない形は `ValueError`)。覚えた形は後から差し込んだ部品にも当てます。既定の部品は送りも折り返しも持たないので、覚えるだけです。
- **Studio の入口から渡す**: 上の 3 つ(部品・規則・形)は `show_params_window` の `strip=`(部品を作る関数。窓がまだ既定の部品の時だけ作って差し込むので、入口を何度通っても部品は 1 つ)・`strip_rule=`・`overflow=` でも渡せます。

  ```python
  show_params_window(win, paths, tr, lang=win._lang, confirm=confirm_action,
                     strip=lambda: studio_panels.flow_classes()["FlowStrip"]("tools", "params"),
                     strip_rule=lambda w, h, now: studio_panels.strip_side(w, h, now, win._panels["strip_mode"]),
                     overflow=win._panels.get("overflow_mode", "scroll"))
  ```

この窓は dock ではないので、`studio_panels.register_panel` / `declare_strip` の台帳(`panel_ledger`)には載りません(載せるのは、窓を浮いたパネルにする時)。見た目の枝の切り替え(`refresh` の `restyle`、`set_overflow_mode` の `set_mode`、`set_strip_mode` の向き)は台帳の列にしか届かないので、この窓へは Studio の側から `set_lang`・`set_overflow`・`set_strip_rule`(同じ規則をもう一度渡すと、すぐ聞き直します)を呼びます。

行の印は次の 4 つです。色だけに頼らず、文字と模様でも分かるようにしてあります。

| 印 | 意味 | 表での見え方 |
|---|---|---|
| ≠ | 束によって値が違う | 行の全部のセルに色。最初の束(基準)と違うセルには角に小さな三角 |
| ◌ | 一部の束にそのキーが無い | 無いセルは空欄 + 斜線 |
| ≈ | 値は同じで書き方が違う(`"0.55 um"` と `"550 nm"`) | 色は付かない |
| ▸ | 直前の実行が読んだ | 色は付かない(セルのツールヒントに、読んだ op と引数) |

未保存のセルは太字です。節の行の印は、その中の行の印をまとめた物です。

検索の欄は、置いた文字が全部見える幅より狭くしません。窓が狭くて道具の帯の隣に収まらない時は、検索の欄が帯の下の段に全幅で入ります(330 px の窓でも切れません)。検索や「違う行だけ」で 1 行も残らない時は、表の場所に「該当なし: "語"」(違う行だけなら「束の間に違う行はありません」)と次の一手のボタン(検索を消す / 全部の行を出す)が出ます。絞り込みを変えると、前の表についての知らせ(写した・保存した など)は消えます。

何も開いていない時は、何をする場所かの 1 行と、「ファイルを開く」「例を開く」のボタンが出ます。窓が小さくて収まらない時は、この案内だけが縦に送れます(文を切りません。2 つのボタンは、横に並べる幅が無ければ縦に並びます)。「例を開く」は同じ装置の昼と夜の 2 つの束(ファイルは作りません)で、違う行・書き方だけ違う行・片方に無い行が 1 つずつ入っています。ファイルを窓へ落としても開けます。束のファイルでない物(画像・フォルダ・ネットの URL・ただの文字)を落とした時は、黙って断らずに下の行へ理由と開ける種類を出します(束のファイルと混ぜて落とせば、束は足します)。

## 値を直す

セルをダブルクリック(または F2、そのまま打ち始める)とその場で編集できます。**値の型は保たれます**。型が変わる入力は断ります。断った時は、欄を閉じずに打った文字をそのまま残し、欄を赤枠にして、理由と例(その欄の今の値)をツールヒントと状態の行に出します(値はそのまま)。直して Enter で確定、Esc で取り消しです。

欄が残るのは、確定のしかたに依りません。Enter・Tab・Shift+Tab のほか、他のセルを押す・検索の欄へ移る・別の窓へ移る(欄からフォーカスが外れる)でも同じです。残っている間は次のようになります。

- 表の描き直し(チェックの切り替え・実行の印・theme や言語の切り替え)では、打った文字は消えません(打っている途中の欄も同じです)。
- 他のセルを編集しようとすると(ダブルクリック・F2・打ち始め)、2 つ目の欄は開かず、断った欄へフォーカスが戻って理由がもう一度出ます。先に直すか、Esc で取り消します。
- 表にフォーカスがある時の Esc は、まず断った欄を取り消します(窓は閉じません)。
- 行の絞り込みや列の出し入れで表を作り直すと、欄は閉じます(値はそのまま)。

| 欄の型 | 入れられる物 | 断る例 |
|---|---|---|
| 真偽 | チェックで切り替え | — |
| 数 | 数のリテラル(`820`、`8.2e2`)。小数の欄に `820` を入れても小数のまま。整数の欄に `320.5` を入れると小数になり、そのことを知らせます | `fast`、`5 mm`(単位が付くと型が変わる)、`nan`、`1+1` |
| 単位つきの数 | 数 + 単位(`600 nm`、`0.6 um`)。同じ次元の中なら単位を変えられます | `600`(単位が無い)、`5 ms`(長さの欄に時間) |
| 文字 | そのまま | `550 nm`(読み直すと単位つきの数になる) |
| 列 | `[800, 600]`(JSON の書き方。`(800, 600)` も可)。長さは変えられます | `[1, "a"]`(数の列に文字を混ぜる)、`640`(列でない) |

数の欄はスピンボックスではなく文字の欄です(桁や指数の書き方を、利用者が書いたとおりに入れられるようにするため)。式は評価しません(`eval` は使っていません。列は `json.loads`、だめなら `ast.literal_eval` で読みます)。

入力は最後に束の門(`ParamBundle` の検査)を通ります。たとえば名前が `_um` で終わる欄に文字列は入りません。門が断った時の知らせは「束の決まりで、この変更はできません(<門が言った理由>)」の形です(門の理由は英語のまま括弧に入ります)。

## 列の間で値を写す

セルを選んで「列へ写す」(または右クリック)から、

- 選んでいる値を別の束へ写す
- 選んでいる束の、違う値の全部を別の束へ写す(1 回の「元に戻す」で全部戻ります)

が選べます。写し先にそのキーが無ければ足します(足したことを知らせます)。写した結果、型が変わった時も知らせます。片方では値・もう片方では節になっているキーは写せません(束の門が断ります)。

## 保存

「保存」は、変更した束を全部、**それぞれ元のファイルへ元の形式のまま**書きます。

1. 同じフォルダの一時ファイルに書く。
2. その一時ファイルを読み手で読み直し、**値も型も**同じことを確かめる。
3. 同じなら `os.replace` で置き換える(原子的)。

どの段で失敗しても元のファイルは 1 バイトも変わらず、一時ファイルは残りません。2 の検算で同じにならない値(下の表の「書けない値」)は、置き換える前に断ります。

書き戻しは**ファイル全体の書き直し**です。次の物は残りません。該当する物がある時は、書く前に一覧を出して確かめます(「それでも保存」で進みます)。

| 失われる物 | どの形式で | 書く前に聞くか |
|---|---|---|
| コメント | YAML(`#`)・TOML(`#`)・XML(`<!-- -->`) | 聞く(行数を出します) |
| YAML のアンカーとエイリアス(`&a` / `*a`) | YAML | 聞く。展開した値で書かれます |
| 参照(`{"$param": "camera.fx"}`) | JSON・YAML | 聞く。参照先の値がただの値として書かれます |
| `include` | JSON・YAML | 聞く。取り込んだファイルの値がこのファイルに書き込まれ、`include` の行は消えます |
| 字下げ・引用符・キーの並び(節ごとにまとめ直す)・数の書き方(`1.50` → `1.5`、`1e3` → `1000.0`) | 全部 | 聞かない(見出しのツールヒントには出ます) |
| 単位の綴り(`µm` → `um`、`kHz` → `khz`) | 全部 | 聞かない。読んだ時点で正規の綴りになります(単位つきの数の数字の字面 `5.50` は保たれます) |

コメントの行数は「`#` で始まる、または空白の後に `#` がある行」を数えた見積もりです(引用符の中の `#` も数えることがあります)。

### 形式ごとの制約

| 形式 | 読む | 書く | 制約 |
|---|---|---|---|
| JSON | `load_params` | できる(既存の `save_params` が書きます) | コメントは元々書けません。NaN / inf は読めません・書けません |
| YAML | `load_params`(PyYAML が要ります。`safe_load` 相当だけ) | できる(PyYAML が要ります) | 文字列は、読み手で別の型に化ける物(`NO`、`010`、`true`、`12:30:00` など)を必ず引用符つきで書きます。列は 1 行(`[640, 480]`)、節は段で書きます |
| XML | `safe_xml.safe_xml_parse` + 下の文法 | できる | DOCTYPE のある XML は読みません。文字列の中の `\r`(XML が改行に畳む)と制御文字は書けません(JSON か YAML へ「名前を付けて保存」してください)。値の無い節は書かれません |
| TOML | `load_params` | **できない**(標準の `tomllib` は読むだけ) | 列は読み取り専用です。比べる・値を他の束へ写す元にはできます。「名前を付けて保存」で JSON / YAML / XML の写しを作ると、その列は写しを指し、編集できるようになります |

「名前を付けて保存」は拡張子で形式が決まります(`.json` / `.yaml` / `.yml` / `.xml`)。保存した後、その列は新しいファイルを指します。

### XML の文法

XML には束の決まった形が無かったので、この窓が読み書きする形を次のように決めています。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<params fullseye_kind="params" version="1">
  <section name="camera">
    <param name="fx" type="float">812.5</param>
    <param name="cx" type="int">320</param>
    <param name="size" type="list">
      <item type="int">640</item>
      <item type="int">480</item>
    </param>
  </section>
  <section name="optics">
    <param name="wavelength" type="quantity">550 nm</param>
  </section>
  <section name="exposure">
    <param name="auto" type="bool">true</param>
    <param name="mode" type="str">global</param>
  </section>
</params>
```

- `type` は `bool` / `int` / `float` / `quantity` / `str` / `list`。この窓が書く時は必ず付けます。
- 手書きで `type` を省いた時は、`true` / `false` は真偽、整数の字面は整数、小数・指数の字面は小数、それ以外は文字(`550 nm` のような文は単位つきの数)と読みます。前後の空白は落とします(`type="str"` を付ければ空白も保たれます)。
- 根の `fullseye_kind` と `version` は省けます。`fullseye_kind` が `params` でない物、`version` がこの版より新しい物は読みません。
- 知らない要素・知らない属性・名前の重複・節の直下の文字は断ります(書き戻すと失われるか、意味が決まらないため)。
- 参照と `include` は XML にはありません。

## 読めないファイル

読めない・壊れている・大きすぎる・安全でないファイルは列にならず、**読み手が言った理由がそのまま**状態の行に出ます(この窓は読み手の門を緩めません)。理由は読み手や OS が返す英語なので、画面の言語の文の後ろに括弧で付けます(「rig.json を開けません(<理由>)」)。他の列には影響しません。断る物の例:

- 無いファイル、フォルダ、知らない拡張子、JSONC / JSON5
- 壊れた JSON / YAML / TOML / XML、UTF-8 でないファイル
- 4 MB を超えるファイル(`parambundle.MAX_FILE_BYTES`。XML も同じ上限)
- JSON のキーの重複・`NaN`・`null`・最上位が辞書でない物・数の欄の文字列
- YAML の python タグ(任意のコードは走りません)、エイリアスの爆発、キーの重複、YAML 1.1 と 1.2 で値が変わる素のスカラー(`NO`、`010`)
- DOCTYPE / ENTITY のある XML、入れ子が深すぎる XML、上の文法に合わない XML
- フォルダの外を指す `include`、循環する参照

同じファイルを 2 度開くと、2 列目は作りません(どちらが正本か分からなくなるため)。名前が同じ別のファイルは、親のフォルダ名を付けて区別します(`night/rig.json`)。

## 外でファイルが変わった時

読んだ時の更新時刻・大きさ・SHA-256 を覚えています。窓が前に来た時に比べ、変わっていれば状態の行に注意を出します。更新時刻だけが変わって中身が同じなら、変更とは見なしません。

外で変わったファイルへ保存しようとすると、黙って上書きせずに聞きます(読み直す / このまま上書き / キャンセル)。消えたファイルも同じです。「読み直す」は未保存の変更を捨ててファイルから読み直します。

`include` で取り込まれた側のファイルの変更は見ていません(見るのは列のファイルだけです)。

## 実行との連動

`ParamsPanel.mark_used(reports)` に、直前の実行の記録を渡すと、読まれたキーの行に ▸ が付きます。渡せる物は、

- `p.for_op(名前, report=True)` が返す `ParamReport`(1 つ、または並び)。束の名前(ファイル名)が合う列に付きます。
- キーの並び(列の番号と一緒に)。

です。印は次に `mark_used` を呼ぶまで残ります。

## 閉じる・戻る

- Esc で閉じます。段があります: 断ったまま残っている欄があれば、まずそれを取り消す → 検索の欄に文字があれば、検索を消す → 閉じる。
- 未保存の変更がある時は、閉じる前に聞きます(保存して閉じる / 保存せずに閉じる / キャンセル)。「保存せずに閉じる」を選ぶと、値は保存済みの物に戻ります。
- 位置・大きさ・「違う行だけ」の状態・開いていたファイルは、Studio と同じ設定の置き場(`FULLSEYE_STUDIO_SETTINGS` の ini があればそちら)の `params_window/` に書かれ、次に開いた時に戻ります。画面の外に出ていた位置は画面の中へ戻します。

## 確認の窓

確認の窓は、Undo で戻せずに何かが失われる時だけ出ます。どれも**既定のボタン(Enter)と Esc はキャンセル**で、ボタンは画面の言語の動詞です(Qt の標準ボタンは使いません)。

| いつ | ボタン |
|---|---|
| 未保存のまま閉じる・開き直す・列を外す | 保存して<閉じる / 開く / 外す> / 保存せずに<閉じる / 開く / 外す> / キャンセル |
| 未保存の列を読み直す | 読み直す / キャンセル |
| 保存で失われる物がある | それでも保存 / キャンセル |
| 読んだ後に外で変わった・消えたファイルへ保存する | 読み直す / このまま上書き / キャンセル |

Studio から開いた時は、Studio の `confirm_action` を `ParamsPanel.set_confirm(fn)` で受け取り、同じ形の窓を出します(`fn(parent, title, text, action, *, kind, buttons)`。`kind` は unsaved / changed / run、答えはボタンの役割の鍵)。単独で開いた時は自前の窓で、形は同じです。

## 言語

画面の文は英語が正で、日本語・簡体字・繁体字・韓国語・ドイツ語・ヒンディー語の訳を `studio_assets/studio_params_i18n.json` に持っています(形は `studio_pyedit_i18n.json` と同じ。言語コードは ja・zh・tw・ko・de・hi)。`studio_params_model.make_tr("ja")` がその言語の `tr` を返します。

- 単独で開く時: `python -m studio_params_qt --lang hi …`。
- Studio から開く時: `show_params_window(…, tr=Studio の tr, lang=言語コード)`。窓は `make_tr(lang, fallback=Studio の tr)` を使います(この窓の表に無い文だけを Studio の `tr` に任せます。差し込んだ `FlowStrip` の送りのボタンの文もこの道で訳されます)。表が持たない言語コードを渡しても断らずに開き、この窓の文は英語になります。
- 開いたまま言語を切り替える時: `ParamsWindow.set_lang(言語コード)`。道具の名前とツールヒント・検索の欄・案内・見出し・数え方・題・知らせの行まで全部その言語で作り直します(中身は変わりません)。`ParamsWindow.set_tr(tr)`(パネルだけなら `ParamsPanel.set_tr(tr)`)も使えますが、渡す `tr` はこの窓の文を訳せる物(`make_tr` の物)にします。Studio の `tr` をそのまま渡すと、窓がほぼ英語になります。

ヒンディー語の訳は、Studio の表(`i18n.json`)の用語に合わせて機械で作った物で、母語の人の校閲は受けていません(Studio の表にも同じ英語の文がある 9 行は、Studio の訳と同じ字です)。

### 色と密度

状態の色(違うセルの地・注意・誤り・断った欄の枠・押せない道具の絵・群の間の線)は、`studio_theme` が使える時はその役割の色(`warn` / `err` / `off` / `line`)、無い時は窓の予備の色です。行の余白・ボタンの一辺・間の px は、`studio_theme` が使える時はその密度の表(`density()` の `row_pad`・`icon_btn`・`icon`・`click_gap`・`group_gap`。詰める / 標準)、無い時は窓の定数(詰めると同じ値)です。

パネルは、初めて見える時と、様式やパレットが変わった時(親の窓の QSS の差し替え = theme や密度の切り替え)に、色と密度を自分で読み直します。`ParamsPanel.apply_theme()` を外から呼んでも同じです(呼ばなくて構いません)。道具のボタンは theme の QSS への宣言 `iconOnly` を持ちます(無いと、QSS の余白で絵が潰れます)。読み手が言った理由(ファイルのどこが、なぜ)は英語のまま文の中に入ります。

## いまは出来ない事

- キーを新しく作る・消す・名前を変える(他の束から写して足すことはできます)。
- コメントや書き方を保ったままの書き戻し。
- TOML への書き戻し。
- `include` された側のファイルを、この窓の中で別の列として追うこと(その値は取り込んだ側の列に見えます。直して保存すると、値は取り込んだ側のファイルに書き込まれます)。
- `p.fx` や `p["camera.fx"]` のように直接読んだキーの記録(`ParamReport` が出来るのは `for_op(..., report=True)` を通した時だけです)。
