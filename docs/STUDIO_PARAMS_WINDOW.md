# パラメータの窓(束を並べて見る・直す)

Fullseye Studio の「パラメータ」の窓の説明です。パラメータの束(`fullseye.load_params` が読むファイル)を、**行 = キー、列 = ファイル**の表に並べて見比べ、その場で直し、元の形式のまま書き戻します。束そのものの決まり(単位、参照、include、op への渡し方)は [PARAM_BUNDLE.md](PARAM_BUNDLE.md) にあります。

実装は 2 つのモジュールです。

| モジュール | 中身 |
|---|---|
| `studio_params_model.py` | 表のモデル(Qt なし)。読む・比べる・絞る・写す・直す・Undo / Redo・書く・外での変更の検出 |
| `studio_params_qt.py` | 窓(PySide6)。道具の帯・木つきの表・状態の 1 行 |

## 開き方

単独で開けます(Studio 本体が無くても動きます)。

```
python -m studio_params_qt rig_day.json rig_night.yaml rig_lab.xml
python -m studio_params_qt --lang ja rig_day.json
python -m studio_params_qt            # 前に開いていたファイルを戻す
```

Studio の中からは `studio_params_qt.show_params_window(parent, paths, tr, confirm=confirm_action)` が入口です。同じ親の窓が既にあれば 2 枚目は作らず、渡したファイルを列に足して前に出します。窓はモードレスで、本体の操作を止めません。`confirm` に Studio の `confirm_action` を渡すと、確認の窓が Studio と同じ形になります(下の「確認の窓」)。

## 画面

上から、道具の帯・表・状態の 1 行です。

- **道具の帯**(アイコンだけのボタン。載せるとツールヒントに名前・何が起きるか・キーが出ます): 開く(Ctrl+O)/ 列を足す(Ctrl+Shift+O)/ 列を外す / 保存(Ctrl+S)/ 名前を付けて保存(Ctrl+Shift+S)/ 読み直す / 元に戻す(Ctrl+Z)/ やり直し(Ctrl+Y。Ctrl+Shift+Z も)/ 列へ写す / 違う行だけ(キーなし。帯のトグルだけ。Ctrl+D は Studio で「複製」なので付けません)/ キーを検索(Ctrl+F)。
- **表**: 1 列目はキー(`camera.fx` の `camera` が節、`fx` が葉。節は折りたためます)、2 列目は行の印、3 列目から束が 1 つずつ。見出しは束の名前で、未保存なら `*`、読むだけの束なら「読み取り専用」と付きます。見出しのツールヒントに、ファイルの場所と、保存すると失われる物が出ます。
- **状態の 1 行**: 束の数・行の数・違う行の数・一部の束に無い行の数・未保存の束の数。右側に、直前の操作の結果や断った理由が出ます(断った時は ✕、注意は ▲)。窓が狭い時は、数え方が印と数だけの短い形になります(全文はツールヒント)。

道具の帯のボタンは、1 つの部品(objectName `panelStrip`)にまとまっています。道具は 1 機能 1 つの `QAction`(`ParamsPanel.tool_actions`)で、ボタン・キー・パネルの一覧はどれも同じ `QAction` を押します。向きは `ParamsPanel.set_strip_side("top" | "left")` で外から変えられます(`left` = 表の左に縦の 1 列、検索の欄は表の上)。列の部品そのものは `set_strip_widget(w)` で差し替えられます(`set_actions(items)` と `set_orientation(o)` を持つ `QWidget`)。収まらない時に「送る」(スクロールのボタン)か「折り返す」(数段組)かは、差し替えた部品が受け持ちます。既定の部品は全部のボタンが見える長さを最小の大きさにします(隠しません)。

行の印は次の 4 つです。色だけに頼らず、文字と模様でも分かるようにしてあります。

| 印 | 意味 | 表での見え方 |
|---|---|---|
| ≠ | 束によって値が違う | 行の全部のセルに色。最初の束(基準)と違うセルには角に小さな三角 |
| ◌ | 一部の束にそのキーが無い | 無いセルは空欄 + 斜線 |
| ≈ | 値は同じで書き方が違う(`"0.55 um"` と `"550 nm"`) | 色は付かない |
| ▸ | 直前の実行が読んだ | 色は付かない(セルのツールヒントに、読んだ op と引数) |

未保存のセルは太字です。節の行の印は、その中の行の印をまとめた物です。

何も開いていない時は、何をする場所かの 1 行と、「ファイルを開く」「例を開く」のボタンが出ます。「例を開く」は同じ装置の昼と夜の 2 つの束(ファイルは作りません)で、違う行・書き方だけ違う行・片方に無い行が 1 つずつ入っています。ファイルを窓へ落としても開けます。

## 値を直す

セルをダブルクリック(または F2、そのまま打ち始める)とその場で編集できます。**値の型は保たれます**。型が変わる入力は断ります。断った時は、欄を閉じずに打った文字をそのまま残し、欄を赤枠にして、理由と例(その欄の今の値)をツールヒントと状態の行に出します(値はそのまま)。直して Enter で確定、Esc で取り消しです。

| 欄の型 | 入れられる物 | 断る例 |
|---|---|---|
| 真偽 | チェックで切り替え | — |
| 数 | 数のリテラル(`820`、`8.2e2`)。小数の欄に `820` を入れても小数のまま。整数の欄に `320.5` を入れると小数になり、そのことを知らせます | `fast`、`5 mm`(単位が付くと型が変わる)、`nan`、`1+1` |
| 単位つきの数 | 数 + 単位(`600 nm`、`0.6 um`)。同じ次元の中なら単位を変えられます | `600`(単位が無い)、`5 ms`(長さの欄に時間) |
| 文字 | そのまま | `550 nm`(読み直すと単位つきの数になる) |
| 列 | `[800, 600]`(JSON の書き方。`(800, 600)` も可)。長さは変えられます | `[1, "a"]`(数の列に文字を混ぜる)、`640`(列でない) |

数の欄はスピンボックスではなく文字の欄です(桁や指数の書き方を、利用者が書いたとおりに入れられるようにするため)。式は評価しません(`eval` は使っていません。列は `json.loads`、だめなら `ast.literal_eval` で読みます)。

入力は最後に束の門(`ParamBundle` の検査)を通ります。たとえば名前が `_um` で終わる欄に文字列は入りません。

## 列の間で値を写す

セルを選んで「列へ写す」(または右クリック)から、

- 選んでいる値を別の束へ写す
- 選んでいる束の、違う値の全部を別の束へ写す(1 回の「元に戻す」で全部戻ります)

が選べます。写し先にそのキーが無ければ足します(足したことを知らせます)。写した結果、型が変わった時も知らせます。片方では値・もう片方では節になっているキーは写せません(束の門が断ります)。

## 保存

「保存」は、変更した束を全部、**それぞれ元のファイルへ元の形式のまま**書きます。

1. 同じフォルダの一時ファイルに書く。
2. その一時ファイルを読み手で読み直し、**値も型も**同じことを確かめる。
3. 同じなら `os.replace` で置き換える(原子的)。

どの段で失敗しても元のファイルは 1 バイトも変わらず、一時ファイルは残りません。2 の検算で同じにならない値(下の表の「書けない値」)は、置き換える前に断ります。

書き戻しは**ファイル全体の書き直し**です。次の物は残りません。該当する物がある時は、書く前に一覧を出して確かめます(「それでも保存」で進みます)。

| 失われる物 | どの形式で | 書く前に聞くか |
|---|---|---|
| コメント | YAML(`#`)・TOML(`#`)・XML(`<!-- -->`) | 聞く(行数を出します) |
| YAML のアンカーとエイリアス(`&a` / `*a`) | YAML | 聞く。展開した値で書かれます |
| 参照(`{"$param": "camera.fx"}`) | JSON・YAML | 聞く。参照先の値がただの値として書かれます |
| `include` | JSON・YAML | 聞く。取り込んだファイルの値がこのファイルに書き込まれ、`include` の行は消えます |
| 字下げ・引用符・キーの並び(節ごとにまとめ直す)・数の書き方(`1.50` → `1.5`、`1e3` → `1000.0`) | 全部 | 聞かない(見出しのツールヒントには出ます) |
| 単位の綴り(`µm` → `um`、`kHz` → `khz`) | 全部 | 聞かない。読んだ時点で正規の綴りになります(単位つきの数の数字の字面 `5.50` は保たれます) |

コメントの行数は「`#` で始まる、または空白の後に `#` がある行」を数えた見積もりです(引用符の中の `#` も数えることがあります)。

### 形式ごとの制約

| 形式 | 読む | 書く | 制約 |
|---|---|---|---|
| JSON | `load_params` | できる(既存の `save_params` が書きます) | コメントは元々書けません。NaN / inf は読めません・書けません |
| YAML | `load_params`(PyYAML が要ります。`safe_load` 相当だけ) | できる(PyYAML が要ります) | 文字列は、読み手で別の型に化ける物(`NO`、`010`、`true`、`12:30:00` など)を必ず引用符つきで書きます。列は 1 行(`[640, 480]`)、節は段で書きます |
| XML | `safe_xml.safe_xml_parse` + 下の文法 | できる | DOCTYPE のある XML は読みません。文字列の中の `\r`(XML が改行に畳む)と制御文字は書けません(JSON か YAML へ「名前を付けて保存」してください)。値の無い節は書かれません |
| TOML | `load_params` | **できない**(標準の `tomllib` は読むだけ) | 列は読み取り専用です。比べる・値を他の束へ写す元にはできます。「名前を付けて保存」で JSON / YAML / XML の写しを作ると、その列は写しを指し、編集できるようになります |

「名前を付けて保存」は拡張子で形式が決まります(`.json` / `.yaml` / `.yml` / `.xml`)。保存した後、その列は新しいファイルを指します。

### XML の文法

XML には束の決まった形が無かったので、この窓が読み書きする形を次のように決めています。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<params fullseye_kind="params" version="1">
  <section name="camera">
    <param name="fx" type="float">812.5</param>
    <param name="cx" type="int">320</param>
    <param name="size" type="list">
      <item type="int">640</item>
      <item type="int">480</item>
    </param>
  </section>
  <section name="optics">
    <param name="wavelength" type="quantity">550 nm</param>
  </section>
  <section name="exposure">
    <param name="auto" type="bool">true</param>
    <param name="mode" type="str">global</param>
  </section>
</params>
```

- `type` は `bool` / `int` / `float` / `quantity` / `str` / `list`。この窓が書く時は必ず付けます。
- 手書きで `type` を省いた時は、`true` / `false` は真偽、整数の字面は整数、小数・指数の字面は小数、それ以外は文字(`550 nm` のような文は単位つきの数)と読みます。前後の空白は落とします(`type="str"` を付ければ空白も保たれます)。
- 根の `fullseye_kind` と `version` は省けます。`fullseye_kind` が `params` でない物、`version` がこの版より新しい物は読みません。
- 知らない要素・知らない属性・名前の重複・節の直下の文字は断ります(書き戻すと失われるか、意味が決まらないため)。
- 参照と `include` は XML にはありません。

## 読めないファイル

読めない・壊れている・大きすぎる・安全でないファイルは列にならず、**読み手が言った理由がそのまま**状態の行に出ます(この窓は読み手の門を緩めません)。他の列には影響しません。断る物の例:

- 無いファイル、フォルダ、知らない拡張子、JSONC / JSON5
- 壊れた JSON / YAML / TOML / XML、UTF-8 でないファイル
- 4 MB を超えるファイル(`parambundle.MAX_FILE_BYTES`。XML も同じ上限)
- JSON のキーの重複・`NaN`・`null`・最上位が辞書でない物・数の欄の文字列
- YAML の python タグ(任意のコードは走りません)、エイリアスの爆発、キーの重複、YAML 1.1 と 1.2 で値が変わる素のスカラー(`NO`、`010`)
- DOCTYPE / ENTITY のある XML、入れ子が深すぎる XML、上の文法に合わない XML
- フォルダの外を指す `include`、循環する参照

同じファイルを 2 度開くと、2 列目は作りません(どちらが正本か分からなくなるため)。名前が同じ別のファイルは、親のフォルダ名を付けて区別します(`night/rig.json`)。

## 外でファイルが変わった時

読んだ時の更新時刻・大きさ・SHA-256 を覚えています。窓が前に来た時に比べ、変わっていれば状態の行に注意を出します。更新時刻だけが変わって中身が同じなら、変更とは見なしません。

外で変わったファイルへ保存しようとすると、黙って上書きせずに聞きます(読み直す / このまま上書き / キャンセル)。消えたファイルも同じです。「読み直す」は未保存の変更を捨ててファイルから読み直します。

`include` で取り込まれた側のファイルの変更は見ていません(見るのは列のファイルだけです)。

## 実行との連動

`ParamsPanel.mark_used(reports)` に、直前の実行の記録を渡すと、読まれたキーの行に ▸ が付きます。渡せる物は、

- `p.for_op(名前, report=True)` が返す `ParamReport`(1 つ、または並び)。束の名前(ファイル名)が合う列に付きます。
- キーの並び(列の番号と一緒に)。

です。印は次に `mark_used` を呼ぶまで残ります。

## 閉じる・戻る

- Esc で閉じます。検索の欄に文字がある時は、1 回目の Esc は検索を消し、2 回目で閉じます。
- 未保存の変更がある時は、閉じる前に聞きます(保存して閉じる / 保存せずに閉じる / キャンセル)。「保存せずに閉じる」を選ぶと、値は保存済みの物に戻ります。
- 位置・大きさ・「違う行だけ」の状態・開いていたファイルは、Studio と同じ設定の置き場(`FULLSEYE_STUDIO_SETTINGS` の ini があればそちら)の `params_window/` に書かれ、次に開いた時に戻ります。画面の外に出ていた位置は画面の中へ戻します。

## 確認の窓

確認の窓は、Undo で戻せずに何かが失われる時だけ出ます。どれも**既定のボタン(Enter)と Esc はキャンセル**で、ボタンは画面の言語の動詞です(Qt の標準ボタンは使いません)。

| いつ | ボタン |
|---|---|
| 未保存のまま閉じる・開き直す・列を外す | 保存して<閉じる / 開く / 外す> / 保存せずに<閉じる / 開く / 外す> / キャンセル |
| 未保存の列を読み直す | 読み直す / キャンセル |
| 保存で失われる物がある | それでも保存 / キャンセル |
| 読んだ後に外で変わった・消えたファイルへ保存する | 読み直す / このまま上書き / キャンセル |

Studio から開いた時は、Studio の `confirm_action` を `ParamsPanel.set_confirm(fn)` で受け取り、同じ形の窓を出します(`fn(parent, title, text, action, *, kind, buttons)`。`kind` は unsaved / changed / run、答えはボタンの役割の鍵)。単独で開いた時は自前の窓で、形は同じです。

## 言語

画面の文は英語が正で、日本語・簡体字・繁体字・韓国語・ドイツ語の訳を `studio_assets/studio_params_i18n.json` に持っています(形は `studio_pyedit_i18n.json` と同じ)。`studio_params_model.make_tr("ja")` がその言語の `tr` を返します。読み手が言った理由(ファイルのどこが、なぜ)は英語のまま文の中に入ります。

## いまは出来ない事

- キーを新しく作る・消す・名前を変える(他の束から写して足すことはできます)。
- コメントや書き方を保ったままの書き戻し。
- TOML への書き戻し。
- `include` された側のファイルを、この窓の中で別の列として追うこと(その値は取り込んだ側の列に見えます。直して保存すると、値は取り込んだ側のファイルに書き込まれます)。
- `p.fx` や `p["camera.fx"]` のように直接読んだキーの記録(`ParamReport` が出来るのは `for_op(..., report=True)` を通した時だけです)。
